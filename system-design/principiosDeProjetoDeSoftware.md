# Principios de Projeto de Software

# Aula 2

1) Quais as consequências de um projeto de software mal feito?
- as consequecias de um projeto de software mal feito podem incluir aumento de custos, atrasos no cronograma, baixa qualidade do produto final, dificuldade de manutenção e evolução do sistema, insatisfação dos usuários e stakeholders, além de possíveis falhas de segurança e desempenho.

2) Em um projeto de software, um requisito sofreu uma alteração e a parte de análise
referente a esta modificação foi refeita. Entretanto, o projetista não conseguiu
encontrar quais artefatos de projeto estavam associados as partes de análise que foram
alteradas.

No caso acima, qual foi o princípio violado no projeto de software?

- O princípio violado no projeto de software foi o princípio da rastreabilidade, que estabelece que todos os artefatos de projeto devem estar relacionados aos requisitos e análises correspondentes, permitindo identificar facilmente quais partes do projeto foram afetadas por alterações nos requisitos.
Ser rastreável à sua especificação.

3) Escolha e explique um dos princípios gerais de projeto de software.

4) Um bom projeto deve possuir todos os modelos e diagramas possíveis documentados
a fim de evitar equívocos? Explique.

- Não, um bom projeto não precisa possuir todos os modelos e diagramas possíveis documentados. O objetivo é ter documentação suficiente para comunicar a arquitetura, os módulos e as interações do sistema de forma clara e compreensível. Documentar excessivamente pode levar a complexidade desnecessária, dificultando a manutenção e evolução do sistema. É importante focar na documentação que agrega valor ao projeto e facilita a compreensão dos desenvolvedores e stakeholders.
